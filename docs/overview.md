# 밑그림 — 무엇을 만드는가

무엇을, 누구를 위해, 어디까지 만들 것인가.
길을 잃었을 때 돌아와 확인하는 문서입니다. **잘 바뀌지 않습니다.**
언제 어떻게 만드는지는 [`plan.md`](./plan.md) 에 있습니다.

---

## 한 줄 정의

> **폰 브라우저에서 여는 영어 회화 상대.**
> 영어로 말을 걸면 화면 속 캐릭터가 입을 움직이며 영어로 답하고, 내가 틀린 표현을 한국어로 짚어준다.

---

## 왜 만드는가

1. **말할 상대가 없다** — 읽기와 듣기는 혼자 되지만 말하기는 상대가 있어야 한다. 그 상대를 구하는 게 제일 어렵다.
2. **사람 앞에서 틀리는 게 부담이다** — 틀릴 걸 알면 입이 안 떨어진다. 상대가 사람이 아니면 그 부담이 사라진다.
3. **시간이 고정되면 못 한다** — 지하철에서 10분, 자기 전 5분처럼 쪼개 쓸 수 있어야 지속된다.
4. **만드는 과정 자체가 목적이다** — 영어 연습 상대가 필요한 동시에, 이런 걸 만들어보는 경험이 목적이다. 그래서 완성도보다 **끝까지 가보는 것**이 우선이다.

4번이 나머지 판단의 기준이 된다. 갈림길에서 빠른 길과 이해되는 길이 갈리면 후자로 간다.

---

## 누가, 어디서 쓰는가

**사용자는 한 명 — 본인.** 남에게 공유하거나 알릴 계획이 없다. 이 사실이 설계를 크게 단순하게 만든다. 로그인도, 회원 관리도, 사람이 몰릴 때의 대비도 필요 없다.

**기준 기기는 안드로이드 폰.** 브라우저 음성 인식이 무료로 잘 동작한다. 여기서 완벽하게 되는 것을 목표로 한다.

**아이패드는 사파리로 열어야 한다.** 크롬 등 다른 앱에서는 음성 인식이 있는 것처럼 보이면서 조용히 실패한다. 자세한 이유는 [`decisions.md`](./decisions.md).

## 화면

화면 하나로 끝난다. 메뉴도 설정 페이지도 없다. **열면 바로 말할 수 있어야 한다.**

```
┌─────────────────────────┐
│  [튜터링]    상황극      │  ← 모드 전환
├─────────────────────────┤
│                         │
│          ( ᴗ ᴗ )         │  ← 말할 때 입이 움직이는 아바타
│                         │
├─────────────────────────┤
│ 나 — "Yesterday I go…"  │
│ AI — "Nice! What did…"  │
│ ┌─────────────────────┐ │
│ │ 교정 · go → went     │ │  ← 한국어 설명
│ └─────────────────────┘ │
├─────────────────────────┤
│   [ 🎤 말하기 ]   [ ⌨ ]  │
└─────────────────────────┘
```

---

## 두 가지 모드

같은 봇이지만 태도가 완전히 다르다. 이 차이를 만드는 것이 3주차의 핵심 작업이다.

### 튜터링 — 틀리면 그 자리에서 짚어준다

```
나   Yesterday I go to the cafe and I drink two coffee.

교정 Yesterday I went to the cafe and drank two coffees.
     어제 일이니 과거형입니다. go→went, drink→drank.
     coffee 는 잔 수를 셀 때 coffees 로 씁니다.

AI   Two coffees! That's a lot. What did you do there?
```

교정을 먼저, 대화를 그다음. 흐름이 조금 끊겨도 배우는 게 우선이다.

### 상황극 — 배역을 끝까지 유지한다

```
점원  Hi there! What can I get started for you?
나    I want a coffee.
점원  Sure thing — hot or iced? And what size?

（대화가 끝난 뒤에 한 번에）
      "I want a coffee" 도 통하지만 조금 딱딱합니다.
      "Can I get a coffee?" 또는 "I'll have a coffee." 가 훨씬 자연스럽습니다.
```

중간에 끊지 않는다. 몰입이 깨지면 상황극이 아니게 된다. 교정은 끝나고 몰아서 보여준다.

## 기능 지도

계획의 절반은 **안 할 일**을 정하는 것이다. 아래 경계를 넘고 싶어질 때마다 이 문서로 돌아온다.

### v1 — 지금 만드는 것 (4주)

- 영어 음성으로 대화 주고받기
- 튜터링 모드 — 즉시 교정 + 한국어 설명
- 상황극 모드 — 시나리오 5개, 사후 교정
- 난이도 선택 (초급 / 중급 / 고급)
- 말소리에 맞춰 입이 움직이는 아바타
- 오늘 대화와 교정 내용 다시 보기
- 폰 홈 화면에 아이콘으로 추가

### v2 — 나중에 생각할 것

- 틀린 표현을 모아 복습 카드로
- 주제별 단어장 · 오답 노트
- 내 목소리 다시 듣기
- 상황극 시나리오 직접 추가
- 연속 학습 일수 표시

### 하지 않을 것

- 사람 얼굴로 만든 고품질 립싱크 영상 — 한 마디에 수십 초, 대화가 성립하지 않음
- 로그인 · 회원가입 — 혼자 쓰는 물건
- 발음 점수 매기기 — 별개의 큰 프로젝트
- 앱스토어 출시
- 남에게 공유하고 홍보하기

## 흔들릴 때 돌아올 원칙

"이거 넣을까 말까" 싶을 때 아래에 비춰본다.

1. **속도가 곧 품질이다** — 회화는 기다리면 끊긴다. 답이 3초를 넘으면 그 기능은 실패로 본다. 아바타를 브라우저에서 그리기로 한 것도 전부 이 원칙 때문이다.
2. **한 기기를 확실하게** — 두 기기를 반쯤 지원하느니 안드로이드 하나를 완전하게. 아이패드는 "되면 좋은" 쪽이다.
3. **열쇠는 서버에만** — API 키는 화면 코드·깃허브·채팅창 어디에도 두지 않는다. 예외 없다.
4. **매주 쓸 수 있는 상태로 끝낸다** — 각 주차의 끝은 항상 "지금 열어서 써볼 수 있는" 상태다. 반쯤 만들다 만 채로 넘기지 않는다.
5. **안 쓰면 실패다** — 기능이 몇 개인지가 아니라 **실제로 며칠 썼는지**로 판정한다. 4주차 합격 기준이 "하루 10분씩 3일 사용" 인 이유다.

## 역할 분담

**클로드가 하는 것** — 코드 작성, 깃허브에 올리기, 오류 수정, 구조 설계, 지시문 다듬기. 손이 가는 일은 전부.

**직접 해야 하는 것 세 가지** — ① 가입과 결제, ② 웹 화면에서 버튼 누르기, ③ **실제 폰에서 마이크에 대고 말해보기.** 이 셋은 클로드가 물리적으로 할 수 없다.
