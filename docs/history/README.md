# 개발일지

**"어떻게 여기까지 왔는가"** 를 남기는 곳입니다.

계획서(`../plan.md`)가 **앞으로 할 일**이라면, 여기는 **실제로 있었던 일**입니다.
둘은 자주 다릅니다. **그 차이가 이 폴더의 존재 이유입니다.**

---

## 언제 쓰나 — "마디"

작업 **마디** 하나가 끝날 때마다 파일 하나를 만듭니다.

**마디의 기준** — *"이 시점의 앱은 이전과 다른 물건이다"* 라고 말할 수 있는 지점.
날짜나 작업량이 아니라 **앱이 달라졌는가**로 끊습니다.

## 마디 목록 (이 표가 기준입니다)

| 파일 | 해당 Day | 이 마디가 끝나면 |
|---|---|---|
| `00-setup.md` | Day 1 | ✅ 계획과 문서가 생겼다 |
| `01-first-deploy.md` | Day 2~3 | ✅ 앱이 인터넷에 존재하고 영어로 답한다 |
| `02-memory.md` | Day 4 | 대화가 이어진다 · **1주차 판정** |
| `03-voice.md` | Day 5~7 | 말하고 들을 수 있다 |
| `04-two-devices.md` | Day 8 | 안드로이드와 아이패드 양쪽에서 된다 · **2주차 판정** |
| `05-tutor.md` | Day 9~11 | 챗봇이 아니라 영어 선생님이다 |
| `06-correction.md` | Day 12 | 교정이 실제로 쓸 만하다 · **3주차 판정** |
| `07-avatar.md` | Day 13~14 | 얼굴이 있고 입이 움직인다 |
| `08-daily-use.md` | Day 15~16 | 매일 쓰는 물건이 되었다 · **최종 판정** |

계획이 바뀌어 마디가 늘거나 줄면 **이 표를 고칩니다.** 이 표가 유일한 기준입니다.

---

## 규칙

- 파일명은 위 표 그대로. 내용은 한국어
- 양식은 [`TEMPLATE.md`](./TEMPLATE.md) 를 그대로 따릅니다
- **잘 안 된 것을 빼지 않습니다.** 막혔던 것과 어떻게 풀었는지가 가장 쓸모 있는 기록입니다
- 오류 문구는 **그대로 옮겨 적습니다.** 요약하면 나중에 검색이 안 됩니다
- 한 번 쓴 일지는 고치지 않습니다. 생각이 바뀌면 다음 일지에 씁니다
- `/milestone` 명령으로 작성합니다. 클로드가 잊으면 그렇게 쳐주세요
