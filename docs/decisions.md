## 2026-08-29 — 대화 모델을 Gemini 3.6 Flash 로 (2.5 Flash 폐기됨)

**정한 것** — `gemini-2.5-flash` → `gemini-3.6-flash`. 모델 이름을 `GEMINI_MODEL` 환경변수로도 바꿀 수 있게 코드를 고쳤다. 환경변수가 없으면 기본값을 쓴다.

**왜** — Day 3 첫 배포에서 실제 호출을 해보니 구글이 이렇게 답했다.

> This model models/gemini-2.5-flash is no longer available to new users.
> Please update your code to use models/gemini-3.6-flash.

2.5 Flash 는 신규 사용자에게 더 이상 제공되지 않는다. 처음 계획을 세울 때의 정보가 그 사이에 낡았다.

**같이 배운 것** — 모델 이름은 생각보다 자주 바뀐다. 그래서 앞으로 같은 일이 생기면 **코드를 안 고치고 Vercel 환경변수만 바꿔도** 되게 해뒀다. 오류 메시지에도 어떤 모델을 썼는지 함께 찍히게 했다.

**API 방식은 바꾸지 않았다** — 구글이 새 방식(Interactions API)을 함께 권했지만, 기존 방식(`generateContent`)도 계속 지원된다. 고장 하나를 고치는 데 구조를 갈아엎지 않는다.

**다시 볼 조건** — **Day 4 에서 한 번 검토한다.** Interactions API 는 대화 기록을 서버가 대신 들고 있어(`previous_interaction_id`), 우리가 Day 4 에 하려는 "문맥 잇기"를 더 간단하게 만들 수도 있다. 그때 비교해 보고 정한다. 또는 3.6 이 다시 낡으면 환경변수만 바꾼다.

## 2026-08-29 — 문서를 저장소에 두기로

**정한 것** — 계획서와 지침을 아티팩트가 아니라 저장소의 `.md` 로 관리한다. `CLAUDE.md` 는 세션 시작 시 자동으로 읽히는 행동 지침, `docs/` 는 참고 문서.

**왜** — 작업 컨테이너는 일정 시간이 지나면 사라지고, 새 세션의 클로드는 이전 대화를 기억하지 못한다. 저장소에 있는 문서만이 세션을 건너 살아남는다.

**원본은 저장소** — 아티팩트는 폰에서 읽기 좋은 표시본이다. 내용이 어긋나면 저장소가 맞다.

**다시 볼 조건** — 문서와 실제 코드가 어긋나기 시작하면. 어긋난 지침은 없느니만 못하다.

## 2026-08-29 — 계획서를 하루 단위로 쪼개기

**정한 것** — 주차 단위 계획을 **Day 1~16** 의 하루 단위 할 일로 다시 씀. 매일 갱신되는 것을 전제로 `현재 상태` 표를 문서 맨 위에 둔다.

**왜** — 주 단위는 "이번 주에 뭘 해야 하지"를 매번 다시 판단해야 한다. 하루 단위면 열자마자 오늘 할 일이 보인다. 처음 하는 영역일수록 판단할 거리를 줄여야 한다.

**다시 볼 조건** — 하루 분량(20~25분)이 계속 넘치거나 계속 남으면 쪼개는 단위를 조정한다.

## 2026-08-29 — 아이패드는 사파리로만

**정한 것** — 기준 기기는 안드로이드 크롬. 아이패드는 **사파리로만** 음성 대화를 지원한다. 그리고 기능 검사가 아니라 **몇 초간 반응이 오는지**로 판단해 타이핑 안내로 넘기는 먹통 감지를 넣는다.

**왜** — 애플 정책상 아이패드의 모든 브라우저는 WebKit 으로 돈다. 그런데 크롬 같은 앱 안의 웹뷰에서는 음성 인식 기능이 **노출되어 있으면서 실제로는 동작하지 않는다**. 오류도 나지 않아서, 기능이 있는지 묻는 방식으로는 걸러낼 수 없다.
근거 — WebKit Bug 239816 "[iOS] Web Speech API doesn't work in WKWebView, but webkitSpeechRecognition is still exposed"

**다시 볼 조건** — 애플이 웹뷰에서 음성 인식을 열어주면. 또는 사파리에서도 너무 불안정하면 녹음 파일을 서버에서 옮겨적는 방식으로 통일한다.

## 2026-08-29 — 호스팅은 Vercel

**정한 것** — 허깅페이스 스페이스 대신 Vercel.

**왜** — 폰만으로 개발할 때는 **푸시 → 자동 배포 → 폰에서 새로고침** 루프가 전부다. Vercel 은 깃허브 저장소를 연결만 하면 이 루프가 바로 돈다. 허깅페이스는 저장소가 따로라 동기화 장치를 하나 더 만들어야 하고, 48시간 안 쓰면 잠들어 깨우는 데 시간이 걸린다. 허깅페이스의 최대 장점인 GPU 는, 아바타를 브라우저에서 그리기로 하면서 필요가 없어졌다.

**다시 볼 조건** — GPU 가 필요한 무거운 모델을 돌리게 될 때. 그때는 허깅페이스를 옆에 하나 더 둔다. 또는 1주차에 배포가 계속 말썽이면 그 자리에서 갈아탄다.

## 2026-08-29 — 아바타는 브라우저가 실시간으로 그린다

**정한 것** — 오픈소스 립싱크 영상(LivePortrait · MuseTalk · SadTalker 계열)을 쓰지 않는다. 소리 크기에 맞춰 입이 움직이는 캐릭터를 브라우저가 직접 그린다.

**왜** — 립싱크 영상은 한 마디에 10~60초가 걸린다. 한 마디 하고 40초를 기다리는 것은 회화 연습이 아니다. 게다가 이런 모델을 호스팅해주는 서비스(fal.ai, Replicate 등)는 오픈소스 모델을 돌려주는 **유료 종량제**지 무료가 아니다. 브라우저 방식은 비용 0원, 대기 0초.

**다시 볼 조건** — 대화가 아니라 "완성된 강의 영상"을 만들고 싶어질 때. 그때는 별도 기능으로 붙인다.

## 2026-08-29 — 대화 모델은 Gemini 2.5 Flash

**정한 것** — Gemini 2.5 Flash. 모델 이름만 바꾸면 갈아탈 수 있도록 코드를 짠다.

**왜** — 무료 등급이 있고 응답이 빠르다. 회화 연습에서는 속도가 곧 품질이다.

**주의** — 무료 등급은 분당 요청 수 제한이 있어 빠르게 연달아 말하면 잠깐 막힐 수 있다. 또 무료 등급은 주고받은 내용이 서비스 개선에 쓰일 수 있다고 안내되므로, 실제 주소·전화번호·회사 기밀은 말하지 않는다. **정확한 한도와 요금은 추측하지 말고 가입 화면에서 확인한다.**

**다시 볼 조건** — 무료 한도에 자주 막히거나 교정 품질이 아쉬울 때.

## 2026-08-29 — 만드는 과정의 이해가 목적이다

**정한 것** — 갈림길에서 **빠른 길과 이해되는 길**이 갈리면 후자를 택한다. 클로드가 혼자 5분에 끝낼 수 있는 일도 왜 그렇게 하는지 설명하면서 진행한다.

**왜** — 사용자가 이 프로젝트를 시작한 동기에 "이런 걸 만들어보는 경험 자체"가 포함되어 있음이 확인되었다. 결과물만 목적이라면 방법론이 맞는지 묻지 않는다.

**다시 볼 조건** — 설명이 부담스러워지고 결과만 빨리 보고 싶어질 때. 사용자가 그렇게 말하면 즉시 바꾼다.
